# 범용 업무 분석 프레임워크

## 1. 요구사항 계약
작업 시작 전에 가능한 범위에서 아래 항목을 분리해 기록한다.

| 항목 | 기록 방식 |
| --- | --- |
| 목표 | 무엇을 결정/개선/설명하는가? |
| 입력 데이터 | 어떤 파일·컬럼·기간·단위인가? |
| 제약 | 예산, 시간, 안전, 품질, 법규, 명시적 금지사항 |
| 산출물 | 코드, 비교표, 보고서, 시뮬레이션 등 |
| 성공 기준 | 정확성, 성능, 실무 유용성, 검증 가능성 |
| 불확실성 | 누락된 정보, 가정, 추가 질문 |

## 2. 데이터 신뢰성 체크
- 파일 목록과 데이터 사전 작성, 실제 행 수와 결측·중복 집계.
- 날짜는 시간대·기간을, 금액은 통화·회계기준을, 비율은 분모를 확인.
- 집계 수준이 다른 데이터(Lot·Wafer·Site, 회사·사업부, 개별·집계)를 함부로 합치지 않는다.
- 누출 가능성이 있는 개인정보·영업비밀은 목적에 필요한 범위로만 처리.
- 제공되지 않은 수치로 채우는 경우 **명시적 가정**을 붙인다. 사실인 척하지 않는다.

## 3. 분석·설계·실행
1. 기존 상태(Baseline)부터 정의.
2. 최소한의 합리적 접근법을 선택하고 이유 기록.
3. 입력 검증·경계 조건·비교 대안 점검.
4. 실제 실행·계산·테스트로 결과 확인.
5. '잘되는 사례' 외에도 실패 조건·반례 점검.

## 4. 결과 검증
- 결과 파일 열리는가? 열 수 없는 산출물은 완료가 아님.
- 단위·총합·비율·경계 조건이 맞는가?
- 사용한 데이터/도구/출처/시간 기준을 재현할 수 있는가?
- 결론을 바꾸는 가정은 무엇이며 민감도는 얼마나 큰가?
- 검증 못 한 것은 검증 못 했다고 분리했는가?

## 5. 보고서 구성
**문제 정의 → 데이터/가정 → 수행 과정 → 결과 및 정량 검증 → 대안/한계 → 권고 및 재확인**.

## 6. 역할 협업(다중 페르소나)
- Domain Expert: 도메인 상식과 제약 점검.
- Analyst: 계산·통계·비교.
- QA/Red Team: 반례·누락·데이터 이상 검사.
- Editor/PM: 통합·최종 전달.

역할 수가 늘어도 '각자 독립 에이전트'가 자동으로 실행되는 것은 아니다. 생성 스크립트는 역할별 지침 문서를 만들고, 실제 동시 실행 기능은 실행 환경과 에이전트 도구에 달려 있다.

## 7. 실무 정지조건
필수 입력이 없거나 법·안전·보안 충돌이 있으면 임의 실행을 멈추고 누락·권한·검증 계획을 보고한다. 모델이 모른다는 이유로 가상의 공정 수치나 실제 회사 정책을 지어내지 않는다.
