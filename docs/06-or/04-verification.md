# 수리최적화 결과를 독립적으로 검증하기

Solver 결과 상태가 성공이어도 모델이 틀렸을 수 있다. 검증 코드는 **Solver 모델과 다른 경로로** 원본 입력·해를 읽고 강제 제약과 목적함수를 재계산한다.

## 5종 검증
1. **입력 검증**: ID 중복, 빈 필수 데이터, 음수 용량·비용, 시간대와 단위 확인.
2. **구조 검증**: 작업 수·변수 범위·자격/금지 조합을 모델에 모두 반영했는가?
3. **강제제약 재검산**: 결과만으로 작업별 정확히 1명·인당 최대 1건·자격 제한을 확인.
4. **목적함수 재계산**: 원본 비용표로 계산한 비용이 보고된 값과 동일한가?
5. **경계·반례**: 해 없음, 동점, 입력 순서 변경, 특정 자원 부족, 시간 제한을 점검.

## '최적'이라는 표현의 조건
- **feasible**: 강제 제약을 만족하는 솔루션이 확인됨.
- **optimal**: 완전탐색 또는 솔버의 최적성 보증 등 근거가 있어야 함.
- **infeasible**: 특정 모델의 해 없음이 확인됨. 모델 입력 오류와 구별.
- **timeout/unknown**: 성능·제약을 점검하고 중단 상태를 기록. 해가 없다고 선언하지 않음.

## 모델과 검증 결과가 충돌할 때
- 결과 공개를 중단하고 원자료·단위·제약 누락을 확인한다.
- Solver에 맞추기 위해 검증 규칙을 바꾸지 않는다.
- 사람이 승인한 변경만 요구조건 장부에 반영한다.

## 테스트용 사례
- `examples/or/assignment.json`: 합성 배정 데이터.
- `scripts/solve_assignment.py`: Python 표준라이브러리 완전탐색(작은 규모 한정).
- `scripts/check_or_contract.py`: 문제정의 JSON 필수 항목 검증.
