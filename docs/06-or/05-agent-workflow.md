# 다중 페르소나 요구사항 수집·모델 검증 워크플로

## 역할을 많이 만드는 것보다 역할 사이의 계약이 중요

| 역할 | 입력 | 산출물 | 검증 |
| --- | --- | --- | --- |
| Interviewer | 요청·관계자 응답 | evidence ledger, 미확인 질문 | 발언과 기록 일치 |
| Modeler | 확인된 요구와 데이터 | 결정변수·제약·목적·수용기준 | 누락·모순 |
| Solver Engineer | 모델과 환경 | 계산 코드, 결과, 종료상태 | 실행·단위 |
| Independent Verifier | 원자료와 결과 | 독립 제약검사, 반례 | 재계산 |
| Integrator | 검증된 결과들 | 의사결정과 제한사항 | 근거 추적 |

## 작동 순서
1. 각 응답의 출처·날짜·확정 상태를 `evidence ledger`에 기록.
2. 모호한 단어(최소, 최대, 가능하면, 반드시, 일단, 운영상)는 인터뷰 질문으로 변환.
3. Modeler는 확인된 규칙만 강제 제약으로 사용. 선호는 목적함수·패널티로 제안하고 근거를 붙임.
4. Solver Engineer는 실행 가능한 환경을 검사하고 적합한 solver/알고리즘을 선택.
5. Independent Verifier는 Solver 코드에 의존하지 않는 검증 루틴으로 재확인.
6. Integrator가 일치하는 결론만 통합하고 미검증 사항을 표시.

## 에이전트가 동시에 실행되지 않아도 된다
- 단일 Codex 환경에서는 역할별 프롬프트를 순차로 읽으며 검토할 수 있다.
- 멀티에이전트 기능이 있다면 각 역할을 별도 작업에 할당하고 산출물을 합성한다.
- n개 역할 지침 생성은 **n개 실행 프로세스 자동 생성과 다르다**.
- 각 역할에 도메인 문서 전체를 넣지 말고 `docs/00-index.md`를 통해 필요한 것만 선택.

## 작동 검증을 위한 체크포인트
- 요구조건이 확정되지 않았으면 '완성된 최적화 모델'이라고 쓰지 않는다.
- 모델 데이터·해·제약 검사 결과가 별도로 저장되어야 재현 가능.
- 사람의 질문 응답을 외부 공개 저장소로 밀어 넣지 않는다.
- 접근 권한이 없는 외부 API 또는 시험 데이터 전송은 하지 않는다.

## 짧은 작업 지시 예시
`AGENTS.md 및 docs/06-or/ 문서를 참조하여 요구사항을 확인하고, 확인된 데이터로만 모델을 만들며, 독립 검증 후 결과를 설명해라. 구현 전 모델 명세를 제시하고 선택 근거를 기록하라.`
