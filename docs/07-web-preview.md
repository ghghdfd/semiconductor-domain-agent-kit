# 웹 IDE 개발 서버 · Browser 미리보기 점검

> 일반 웹 개발 환경에서 통용되는 안내입니다. 특정 시험 플랫폼의 비공개 접속 주소·화면·내부 설정은 포함하지 않습니다.

## 언제 읽는가

웹앱, 대시보드, API 데모를 구현하고 IDE 내 Browser/Preview 패널에서 직접 실행·확인할 때만 읽습니다. 백엔드 처리나 CLI 전용 작업에 웹 서버를 억지로 만들 필요는 없습니다.

## 최소 절차

1. **기존 프로젝트 확인:** 실제 작업 디렉터리의 `README.md`, `package.json`, 사용 언어·프레임워크를 확인합니다. 이미 제공된 시작 명령이 있으면 그것을 우선합니다.
2. **서버 실행:** 해당 프레임워크의 개발 서버를 시작합니다. IDE 외부의 프리뷰 패널과 통신할 수 있는 환경이라면 필요한 경우 서버를 `0.0.0.0`에 바인딩합니다. `0.0.0.0`은 '모든 네트워크 인터페이스에서 수신'을 의미하며 브라우저에 입력할 URL 자체는 아닙니다.
3. **실제 포트 확인:** 서버 로그가 표시하는 **실제 리스닝 포트**를 확인합니다. `3000`은 예시일 뿐 고정값이 아닙니다. 프레임워크가 포트 충돌로 다른 번호를 선택했을 수도 있습니다.
4. **미리보기 열기:** IDE가 제공하는 Browser/Preview 기능에서 **포트**와 **경로**(처음에는 `/`)를 설정하고 새로고침합니다. 미리보기용 주소를 임의로 조합하거나 외부 터널을 만들지 않습니다.
5. **기능 검증:** 화면이 뜨는 것만으로 완료 처리하지 말고 실제 버튼·입력·이동·데이터 로딩·오류 메시지를 점검합니다.
6. **프로세스 유지:** 확인하는 동안 서버를 띄운 터미널/세션을 닫지 않습니다. 종료하거나 중단하면 브라우저 연결도 끊어집니다.

## 일반적인 시작 명령 예제

실제 프로젝트가 아래 기술을 사용하는 경우에만 적용합니다.

```bash
# 정적 HTML / Python 표준 라이브러리
python -m http.server 3000 --bind 0.0.0.0

# Vite (package.json에서 dev 스크립트가 정의되어 있을 때)
npm run dev -- --host 0.0.0.0 --port 3000

# Next.js (dev 스크립트가 next dev일 때)
npm run dev -- --hostname 0.0.0.0 --port 3000
```

`3000`은 모두 **예시**입니다. 과제나 기존 프로젝트에서 별도 포트를 요구하면 그 값을 사용합니다. 의존성 설치가 필요하다면 먼저 환경 규정과 기존 설치 여부를 확인하세요. 금지된 외부 통신·서비스·패키지 설치를 우회하지 않습니다.

## '연결 대기'·'페이지를 찾을 수 없음'일 때

| 증상 | 확인할 항목 | 대응 |
| --- | --- | --- |
| 응답하는 서버가 없음 / 연결 실패 | 실행 로그·프로세스 종료 여부 | 서버를 재실행하고 오류를 먼저 수정 |
| 터미널에서는 실행 중인데 미리보기 연결 실패 | 실제 포트, `127.0.0.1` 전용 바인딩 여부 | 환경에서 요구하면 `0.0.0.0` 바인딩으로 다시 실행 |
| 루트 화면은 뜨지만 하위 페이지 실패 | 입력한 경로, 애플리케이션 라우팅 | 우선 `/`로 확인한 다음 실제 경로 사용 |
| 웹 화면은 뜨는데 기능이 동작하지 않음 | 브라우저 오류·서버 로그·API 연결 | 입력 → 처리 → 출력 흐름에 따라 재현·검증 |
| 포트 사용 중 | 로그의 주소 충돌 메시지 | 기존 프로세스를 확인하고 허용된 다른 포트로 실행 |

원한다면 터미널에서 **서버가 실제 응답하는지** 확인할 수 있습니다(`curl`이 설치돼 있을 때).

```bash
curl -v http://127.0.0.1:3000/
```

여기서 `127.0.0.1`은 **서버가 실행 중인 같은 작업 환경에서의 터미널 점검 주소**입니다. IDE Browser에 넣을 주소와는 다를 수 있습니다.

## 보안과 결과 검증

- 공개 저장소에 사내 IP·접속 토큰·개인별 시험 링크·응시환경 화면·과제 내용을 기록하지 않습니다.
- 개발 서버를 `0.0.0.0`에 바인딩할 때는 실제 배포·외부 노출 범위를 확인합니다. 보안 통제가 없는 공용 네트워크에 무심코 노출하지 않습니다.
- Browser 자동 조작은 **해당 환경의 허용 규정**에 따릅니다. 자동화가 금지된 환경에서는 수동으로 기능을 점검합니다.
- 결과 보고에는 사용한 시작 명령, 실제 포트, 성공한 화면/기능, 남은 오류를 기록하되 이를 허가 없이 외부 전송하지 않습니다.
