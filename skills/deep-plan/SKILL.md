# Deep Plan — Codex 호환판

기반: 사용자 제공 `my_skill.zip/deep-plan/SKILL.md`. **Planner / Architect / Critic**의 합의·반론·근거 검증 아이디어를 유지하되 Opus, Tavily MCP, 병렬 서브에이전트 요구를 제거한 경량판이다.

## 실행 환경의 제약

- 사용자에게 보여주는 **모든 내용과 문서는 한국어**로 작성.
- 현재 승인된 Codex 모델만 사용. Opus/Claude/Astra/개인 API·외부 모델은 요구하지 않는다.
- 별도 서브에이전트 기능이 없으면 **현재 한 세션에서 역할을 순차로 전환하여 검토**한다. 이 경우 '독립 에이전트의 확인'이라고 주장하지 않는다.
- WebSearch, Tavily, 기타 MCP를 전제하지 않는다. 사용 가능하고 허용된 자료·도구로만 사실을 확인한다.
- 결과물을 참고 지식 저장소에 저장하거나 Git Push하지 않는다. 실제 과제 디렉터리에서 작업한다.

## 복잡도 선택
- `quick` (기본): 범위가 작고 되돌리기 쉬운 일. **Planner → Critic**, 1회.
- `standard`: 선택지·트레이드오프가 있음. **Planner → Architect → Critic**, 최대 2회.
- `deep`: 되돌리기 어려운 고위험 의사결정. 세 역할 검토 최대 3회.

시간이 제한되면 증거 확보와 구현 검증에 우선순위를 둔다. 사용자가 요구하지 않은 과도한 회의·라운드를 추가하지 않는다.

## 1. 문제 정의

의사결정 대상, 현재 기술·데이터, 제약, 성공 기준, 제한 시간, 반드시 승인받아야 할 결정을 구분한다. 결정이 진행을 막고 자료로 확인되지 않는 경우에만 질문한다.

## 2. 근거 수집

- 로컬 README, 코드, 테스트, 공식 지침, 명시적으로 허용된 공개 자료를 확인한다.
- 사실을 **Verified**(출처와 직접 일치), **Inferred**(해석), **Unknown**(확인 불가)으로 구분한다.
- 시의성이 큰 데이터는 확인일을 기록하고 이전 버전과 비교한다.
- 인터넷 사용 불가 시 추론을 공식 검증으로 포장하지 않는다.

## 3. Planner — 제안

2~3개의 실현 가능한 대안과 장단점·적용 조건을 비교한다. 목표, 핵심 가정, 수용기준, 구현 단계, 리스크를 기록한다. 대안이 하나라면 억지로 늘리지 않는다.

## 4. Architect — 가장 강한 반론

Planner의 선택과 반대되는 입장의 최선의 근거를 제시한다. 성능, 보안, 운영 복잡도, 제약 미반영, 데이터 부족, 실패 시 복구 경로를 점검한다.

## 5. Critic — 검증 관문

원칙과 대안의 정합성, 비교의 공정성, 수용 기준의 테스트 가능성을 검사한다. 코드에 대한 실제 실행 테스트와 모델·요구의 논리 검증을 구별한다.

## 6. 결과와 종료

- **추천안 / 근거 수준 / 대안 비교 / 위험 / 반증 조건 / 검증 계획** 형식으로 보고한다.
- 합의되지 않은 항목은 미합의·미확인으로 표시한다.
- 별도 요청이 있으면 현재 작업 디렉터리에 ADR을 작성한다.
- 비전문가 설명이 필요할 때만 `easy-explainer`를 활용한다.
